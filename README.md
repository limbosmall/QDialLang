## О языке

QDialLang - DSL, компилируемый в байткод, который исполняется VM. Предназначен для написания диалогов и квестов, а также поддерживает возможность катсцен. Позиционирует себя как переносимый язык, компилирующийся в плоский байт-код, который может исполнять любая программа, реализовавшая примитивную виртуальную машину из [приложения А](#приложение-а-спецификация-байткода).

Язык описывает, что происходит в сцене, методом чёрного ящика. Всё, что зависит от игры - команды, иконки, глобальные флаги - приходит
извне, через манифест (написанный по шаблону из [приложения Б](#приложение-б-шаблон-манифеста)) и строго контролируется по указанным там шаблонам. Таким образом, манифест реализует строгую связь между интерфейсом, используемым в скрипте QDialLang и реализацией, предоставляемой платформой.

Документация языка находится в [language](./docs/language.md)

## Преимущества языка

- В силу строгой проверки интерфейсов из манифестов, рекомендуется реализация такого же механизма проверки и на стороне исполняющей программы, что значительно снижает шанс расхождения определённого интерфейса и его реализации, в силу отлова опечатки с обеих сторон, а также выявление ошибки в приложении на этапе сборки, а не посреди выполнения.

- Байткод чрезвычайно переносим: на данный момент реализовано 34 опкода, каждый с двумя числовыми параметрами. Любые примитивные виртуальные машины способны реализовать инструкции, записанные в файл.

- Так как строк в байткоде `.qbc` нет, то перевод и правка текста написанного - это замена `.qstr` без перекомпиляции скрипта.

- Простота байткода поддерживает явное состояние виртуальной машины: при использовании одного из примитивных видов виртуальных машин - стековых, их состояние можно сериализовать почти даром, и состояние VM сериализуется тривиально.

- Разделения режимов "монолог / диалог" с запретом конструкций на уровне компилятора предоставляют удобные мягкие рамки для пользователя

## Дальнейшие планы

В следующих версиях QDialLang предполагается:
- Логические операторы, чтобы избежать излишней вложенности проверок.
- Условные варианты, при выборе варианта ответа в choice.
- Комментарии ";".
- Экранирование.
- Пересмотр локализации, а также связи `.qbc` с `.qstr` : реплика делится тегами на фрагменты (переводчик теряет контекст и не может переставить теги), одинаковые строки дедуплицируются (а в другом языке их может понадобиться перевести по-разному).

## Приложение А: спецификация байткода

Раздел нужен тем, кто пишет виртуальную машину для выбранной программы.

### Формат `.qbc`

Little-endian, поля фиксированной ширины.

|Поле|Размер|Значение|
|---|---|---|
|magic|4 б|`QBC1`|
|manifestVersion|4 б|int32, версия манифеста|
|format|1 б|0 = диалог, 1 = монолог|
|localSlotCount|4 б|int32, сколько слотов локальных завести|
|numberCount|4 б|int32|
|instrCount|4 б|int32|
|числа|8 б × numberCount|double|
|инструкции|9 б × instrCount|1 б опкод + 4 б A + 4 б B|

### Формат `.qstr`

|Поле|Размер|Значение|
|---|---|---|
|magic|4 б|`QST1`|
|stringCount|4 б|int32|
|записи|-|id (4 б) + длина в байтах (4 б) + UTF-8|

### Опкоды

Номер = позиция в таблице, начиная с нуля.

| №     | Опкод                     | A                    | B                          | Действие                                                |
| ----- | ------------------------- | -------------------- | -------------------------- | ------------------------------------------------------- |
| 0     | TextChunk                 | id строки            | -                          | Выдать кусок текста                                     |
| 1     | Cmd                       | id команды           | число аргументов           | Снять аргументы со стека, вызвать команду               |
| 2     | SetSpeed                  | -                    | -                          | Снять 1 значение, сменить скорость печати               |
| 3     | SetPos                    | x                    | y                          | Позиция окна                                            |
| 4     | Icon                      | id иконки            | кадр                       | Показать иконку                                         |
| 5     | Await                     | id глобальной        | -                          | Пауза до выполнения условия                             |
| 6     | PushConst                 | индекс числа         | -                          | Положить константу на стек                              |
| 7     | GetVar                    | слот                 | -                          | Положить локальную на стек                              |
| 8     | SetVar                    | слот                 | -                          | Снять со стека в локальную                              |
| 9     | GetGlobalVar              | id                   | -                          | Положить глобальную на стек                             |
| 10    | SetGlobalVar              | id                   | -                          | Снять со стека в глобальную                             |
| 11    | InterpolateLocal          | слот                 | -                          | Выдать значение локальной как текст                     |

| 13–16 | Add, Sub, Mul, Div        | -                    | -                          | Снять 2, положить 1                                     |
| 17–22 | Eq, Neq, Lt, Gt, Lte, Gte | -                    | -                          | Снять 2, положить 1 (0 или 1)                           |
| 23    | Neg                       | -                    | -                          | Снять 1, положить 1                                     |
| 24    | Jump                      | адрес                | -                          | Безусловный переход                                     |

| 26    | ChoiceBegin               | -                    | -                          | Начало списка вариантов                                 |
| 27    | ChoiceOption              | id строки            | адрес                      | Вариант выбора                                          |
| 28    | ChoiceEnd                 | -                    | -                          | Пауза до выбора игрока                                  |

| 32    | Wait                      | индекс числа         | -                          | Пауза на указанное число секунд                         |
| 33    | Input                     | id глобальной        | тип (0 = number, 3 = text) | Пауза до ввода игрока; значение в глобальную пишет игра |

Новые опкоды всегда дописываются в конец таблицы, чтобы номера существующих не сдвигались и старый байткод не начинал означать другое.

### Модель выполнения: Базовая стековая виртуальная машина

Виртуальная машина хранит указатель инструкции, стек значений (числа, логические значения кодируются как 0 и 1) и массив слотов локальных переменных. Она выполняет инструкции подряд без остановок, пока не встретит одну из пяти точек паузы: `EndLine`, `ChoiceEnd`, `Await`, `Wait`, `Input`. В этот момент она запоминает, чего именно ждёт, и возвращает управление платформе - до тех пор, пока та не сообщит, что событие произошло.

Значения глобальных переменных машине не принадлежат: она читает и пишет их через интерфейс, предоставленный платформой, обращаясь по числовому id из манифеста.

Стек значений сбалансирован по построению: к моменту схождения любых ветвлений его глубина одинакова независимо от пройденного пути.

### Числа

Две реализации VM должны показать игроку одно и то же, поэтому арифметика
определена полностью.

- **Стек** хранит `double` (IEEE 754, 64 бита). `Add`, `Sub`, `Mul`, `Neg` и
  деление на ненулевое число - обычная арифметика `double`, без округления:
  `5 / 2` на стеке - это `2.5`.
- **Деление на ноль** (`Div` с делителем `0`) не даёт ни бесконечности, ни
  ошибки, а насыщается по знаку делимого:

| Делимое  | Результат                     |
| -------- | ----------------------------- |
| больше 0 | `2147483647` (максимум int32) |
| меньше 0 | `-2147483648` (минимум int32) |
| 0        | `0`                           |
Это определено в самом `Div`, а не при записи в переменную, поэтому
  бесконечность не может уйти платформе через аргумент команды или сравнение.
- Запись в локальную (`SetVar`) приводит значение к целому int32: дробная
  часть отбрасывается (к нулю: `2.7` → `2`, `-2.7` → `-2`), значение за
  пределами int32 насыщается до границы, `NaN` становится `0`. Поэтому
  `int x = 5 / 2` даёт `2`, но `if 5 / 2 == 2` - ложь: до записи значение
  дробное.
- Слоты локальных при запуске равны `0` и дальше обнуляются только записью.
  Переход через объявление его не выполняет, поэтому локальная хранит последнее
  записанное значение (при первом проходе - `0`). Компилятор гарантирует, что у
  каждой локальной верхнего уровня свой слот; общий слот бывает только у
  локальных соседних веток `if`/`else`, а их до объявления прочитать нельзя.
  Переход через объявление, после цели которого локальная читается, компилятор не пропускает, так что в корректном байткоде это не встречается.
- Сравнения (`Eq` ... `Gte`) - точное сравнение `double`, результат `0` или
  `1`. `JumpIfFalse` переходит только при `0`; любое другое значение, в том
  числе отрицательное, - истина.
- `InterpolateLocal` выводит целое десятичными цифрами ASCII: без дробной
  части, без разделителей разрядов, без `+`, со знаком `-` у отрицательных.
  Ноль - всегда `0`, не `-0`.
- `InterpolateGlobal` форматирует платформа: значение глобальной ей
  принадлежит, и как показать дробь или текст, решает она.
- `SetGlobalVar` передаёт значение платформе как есть, без приведения.
- Операции VM `NaN` и бесконечностей не порождают. Платформа не должна отдавать
  их в глобальных: тогда их нет в VM вовсе.

### Что легко сделать неправильно

- Порядок аргументов `Cmd`. Компилятор кладёт аргументы в обратном порядке, поэтому первое снятое со стека значение - первый аргумент команды. `B` всегда равен полной арности: опущенные аргументы компилятор уже подставил из `default` манифеста, VM о дефолтах ничего не знает.
- Значения на стеке - только `double`. `bool` - 0 или 1, имя из enum-секции - его числовой id. Текст на стек не попадает никогда: `InterpolateGlobal` берёт у игры уже готовую строку.
- Выбор. `ChoiceOption` между `ChoiceBegin` и `ChoiceEnd` только копят варианты (`A` - id текста кнопки, `B` - адрес). На `ChoiceEnd` VM встаёт на паузу, а после ответа игрока переходит по адресу выбранного варианта.
- Флаги `EndLine`. `A = 1` - подсказка "строка не требует отклика": VM паузится как обычно, решать, ждать ли игрока, - платформе. `B = 1` - последняя строка окна: это сигнал закрыть окно, отдельного опкода для этого нет.
- Пауза посреди строки. `Wait` и `Input` могут стоять внутри реплики, до её `EndLine`: окно при этом остаётся открытым. Таймер `Wait` и поле `Input` нужно показывать после того, как допечатан уже полученный текст, иначе пауза съестся печатью.

## Приложение Б: Шаблон манифеста

Манифест - это весь контракт между скриптами и игрой. Компилятор и IDE знают об игровой стороне ровно то, что в нём написано: имена, типы, сигнатуры. Что команда делает, их не касается. Поэтому один и тот же скрипт переносится между проектами вместе со своим манифестом.

Рекомендуется печь манифест на платформе (движке, игре) автоматически, а компилятор и IDE его только читают. Формат - JSON: читается он на этапе сборки и в IDE, а не в игровом цикле. Во время выполнения байткод оперирует числовыми id, а соответствие "id -> поведение" живёт в реализации самой платформы.

### Шаблон

```json
{
  "version": 7,

  "commands": [
    { "id": 0, "name": "shake", "namespace": "camera",
      "args": [ { "name": "amplitude", "type": "number" } ],
      "doc": "Тряска камеры" },
    { "id": 1, "name": "unlock", "namespace": "state",
      "args": [ { "name": "object", "type": "string", "enum_section": "objects" } ] },
    { "id": 2, "name": "mono_toggle", "namespace": "ui",
      "args": [ { "name": "hold", "type": "bool", "default": false } ] },
    { "id": 3, "name": "set_frenzy", "absent": true },
    { "id": 4, "name": "old_fade", "deprecated": true, "args": [] }
  ],

  "enums": {
    "objects":    [ { "id": 0, "name": "OakBark" },
                    { "id": 1, "name": "OldStump", "absent": true } ],
    "sideimages": [ { "id": 0, "name": "wolf" },
                    { "id": 1, "name": "fox" } ]
  },

  "globals": [
    { "id": 0, "name": "quest_flag_A",       "type": "bool" },
    { "id": 1, "name": "tutorial.p_clicked", "type": "bool", "stored": false },
    { "id": 2, "name": "player.name",        "type": "text" },
    { "id": 3, "name": "shop.qty",           "type": "number", "doc": "Сколько купить" }
  ],

  "icons": [
    { "id": 0, "frames": 4 },
    { "id": 1, "frames": 2 }
  ]
}
```

Все секции необязательны: `{ "version": 1 }` - тоже корректный манифест. Поля, которых нет в описании ниже, читатель пропускает, так что их можно добавлять для своих инструментов, не ломая компилятор.

### `version`

Целое число. Платформа увеличивает его при каждой запечке, которая что-то изменила. Версия штампуется в каждый `.qbc` (`manifestVersion`, см. [приложение А](#приложение-а-спецификация-байткода)) и сверяется при загрузке.

### `commands` - игровые команды

Вызываются в скрипте как `[cmd имя аргументы]`.

| Поле         | Тип    | Обязательно | Значение                                                                                                    |
| ------------ | ------ | ----------- | ----------------------------------------------------------------------------------------------------------- |
| `id`         | int    | да          | Номер команды в байткоде. Не переиспользуется никогда                                                       |
| `name`       | string | да          | Имя в скрипте. Плоское и уникальное во всём манифесте                                                       |
| `namespace`  | string | нет         | Только для группировки в инструментах. На язык не влияет: `[cmd shake]` пишется без него                    |
| `args`       | массив | нет         | Сигнатура, см. ниже. Нет - команда без аргументов                                                           |
| `doc`        | string | нет         | Описание для подсказок в IDE                                                                                |
| `deprecated` | bool   | нет         | Устарела, но работает: компиляция проходит с предупреждением. Ставит автор команды                          |
| `absent`     | bool   | нет         | Команда удалена - "надгробие" (см. ниже). Вызов даёт ошибку "команда удалена". Ставит бейкер (рекомендация) |

#### Аргументы

| Поле           | Тип     | Обязательно  | Значение                                                         |
| -------------- | ------- | ------------ | ---------------------------------------------------------------- |
| `name`         | string  | нет          | Имя для подсказок и сообщений об ошибках                         |
| `type`         | string  | да           | `number`, `bool` или `string`                                    |
| `enum_section` | string  | для `string` | Какая enum-секция разрешает имя в id                             |
| `default`      | по типу | нет          | Значение по умолчанию, такие аргументы можно опускать при вызове |

Что принимает аргумент каждого типа:

| `type`   | В скрипте                                                                                 | В байткоде |
| -------- | ----------------------------------------------------------------------------------------- | ---------- |
| `number` | число (в том числе отрицательное и дробное), `int`-локальная или глобальная `number`      | `double`   |
| `bool`   | только `true` / `false` (не `0` / `1`) или глобальная `bool`                              | 0 / 1      |
| `string` | **имя из enum-секции** (`OakBark` или `"OakBark"`) либо его числовой id. Переменные - нет | id         |

`string` означает не произвольный текст, а имя из перечисления: в байткоде строк нет. Тип `text` у аргументов команд запрещён - он бывает только у глобальных.

Аргументы с `default` должны идти в конце списка. Опущенные значения подставляет компилятор в момент сборки, поэтому смена `default` в манифесте не доходит до уже скомпилированных `.qbc` без перекомпиляции. Для `string` `default` - имя из секции или его id.

### `enums` - перечисления

Объект имя "секции -> массив значений". Нужны там, где в скрипте пишут имя, а в байткод должно попасть число: строковые аргументы команд и имена иконок.

|Поле|Тип| Значение                                                                                                                    |
|---|---|---|
|`id`|int| Число, которое попадёт в байткод                                                                                            |
|`name`|string| Имя в скрипте. **Не может начинаться с цифры**: в тех же местах легален и числовой id, и различаются они по первому символу |
|`absent`|bool| Значение удалено: обращение даёт "значение удалено", id не освобождается                                                    |

Секции однородны: только `id`, `name` и `absent`. Всё, что у сущности есть сверх адресации (например, число кадров у спрайта), живёт в отдельной таблице - см. `icons`.

### `globals` - глобальные переменные

Живут в игре, а не в VM: VM читает и пишет их через интерфейс платформы по id. Поэтому флаг, выставленный в диалоге, видят другие системы игры, и он переживает сохранение.

| Поле     | Тип    | Обязательно | Значение                                                                                                                |
| -------- | ------ | ----------- | ----------------------------------------------------------------------------------------------------------------------- |
| `id`     | int    | да          | Номер в байткоде                                                                                                        |
| `name`   | string | да          | Имя без `$`. **Неймспейс - часть имени**, через точку: `tutorial.p_clicked` пишется в скрипте как `$tutorial.p_clicked` |
| `type`   | string | да          | `number`, `bool` или `text`                                                                                             |
| `stored` | bool   | нет         | По умолчанию `true`. `false` - производная: значение вычисляет игра, запись из скрипта - ошибка компиляции              |
| `doc`    | string | нет         | Описание для подсказок в IDE                                                                                            |

Глобальная типа `text` (например, имя игрока) допустима только в интерполяции `[$player.name]` и как цель `[input]`. В выражениях, условиях, присваиваниях и аргументах команд она даёт ошибку компиляции.

### `icons` - кадры иконок

Сколько кадров в листе спрайтов у каждой иконки. Своей нумерации у таблицы нет: `id` берутся из enum-секции спрайтов (в примере - `sideimages`).

|Поле|Тип|Значение|
|---|---|---|
|`id`|int|id из enum-секции спрайтов|
|`frames`|int|Число кадров. Компилятор проверяет по нему второй аргумент `[ico имя кадр]`|

Какая из секций описывает спрайты, манифест не говорит: язык этого не знает. Имя секции задаётся в настройках компилятора (`CompilerOptions.IconSection`, в IDE - настройка проекта). Если секция не задана, `[ico]` принимает только числовые id.

### Рекомендации стабильности id

Номера вкомпилированы в уже собранные `.qbc`, поэтому:

- id не переиспользуются. Удалённая команда или значение перечисления не исчезает из манифеста, а остаётся с `"absent": true` - это "надгробие". Следствия: новый id - всегда `max + 1`, а компилятор может сказать "команда удалена" вместо "неизвестная команда".
- Восстановление команды с тем же именем возвращает ей прежний id.
- Переименование - это удаление и создание: у нового имени новый id, а уже скомпилированные `.qbc` со старым id сломаются. Их нужно пересобрать.
- Порядок записей не важен: id задаются явно, а не позицией в массиве.

`deprecated` и `absent` намеренно разные поля: первое ставит автор ("не используйте"), второе - рекомендуемый бейкер ("ресурса больше нет").

### Что проверяется при чтении

Манифест с этими ошибками не загружается: виновата сторона, которая его пишет, и молча продолжать было бы хуже.

- аргумент типа `string` без `enum_section` или со ссылкой на несуществующую секцию;
- аргумент типа `text`;
- аргумент без `default` после аргумента с `default`;
- `default` не того типа или не найденный в своей секции;
- неизвестный `type` у аргумента или глобальной.

Аргументы "надгробий" не проверяются: они могут ссылаться на то, чего уже нет. Целые числа, записанные как `3.0`, принимаются: JSON-сериализаторы многих движков пишут числа как float.

### Рекомендации для бейкера

- Перед записью сравнивайте новый манифест со старым по значению и увеличивайте `version`, только если что-то изменилось. Иначе версия растёт на каждой запечке, и сверка при загрузке теряет смысл.
- Нормализуйте id к целым перед записью.
- Дубликат имени команды между неймспейсами - ошибка запечки: имена плоские.
- Проверяйте на своей стороне то же, что проверяет компилятор: тогда расхождение "объявлено в манифесте, но не реализовано" ловится до запуска.
