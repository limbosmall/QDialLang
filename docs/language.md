# QDialLang - справочник языка

Справочник для автора сценариев. Что такое QDialLang и чем он отличается от
похожих языков - в [README](../README.md).

Язык для написания диалогов и квестов. Компилируется в переносимый байткод,
не привязанный ни к какому движку: `.qbc` может исполнить любая программа,
реализовавшая виртуальную машину по [спецификации байткода](../README.md#приложение-а-спецификация-байткода).

Язык описывает что происходит в диалоге, но не как это выглядит и что
делает игра. Всё игровое - команды, иконки, глобальные флаги - приходит
извне, через манифест, который печёт движок. Поэтому один и тот же скрипт
переносится между проектами вместе со своим манифестом.

## 1. Структура файла

Исходный файл сценария имеет расширение `.qdscr`. Это обычный текст в
UTF-8; расширение нужно инструментам, чтобы отличать сценарии от всего
остального, на сам язык оно не влияет.

Первой значащей строкой файла обязана быть директива формата:

```
@dialogue_format_monologue
```

или

```
@dialogue_format_dialogue
```

Она не просто помечает файл - она включает и выключает части языка
(см. [раздел 3](#3-режимы-монолог-и-диалог)). Файл без директивы не
компилируется.

Дальше идёт последовательность конструкций верхнего уровня: регионы, точки,
вызовы компонентов, условия, присваивания. Выполнение начинается с первой
инструкции файла и идёт сверху вниз, пока не встретит `halt` или конец файла.

## 2. Общие правила синтаксиса

**Отступы не значат ничего.** Ведущие пробелы и табы отбрасываются, вложенность
задаётся только фигурными скобками. Отступы в примерах - только для чтения.

**Одна конструкция - одна строка.** Всё лишнее, дописанное после валидной
конструкции на той же строке, вызовет ошибку компиляции, а не будет
проигнорировано.

**Фигурные скобки - каждая на своей строке:**

```
:text_Default
	{
	Текст реплики.
	}
```

Вот так работать не будет:

```
:text_Default { Текст реплики. }
```

**Пустые строки игнорируются** - и в коде, и внутри текстовых блоков.

**Комментариев в языке нет** - ни `#`, ни `//`: такая строка даст ошибку
компиляции. Комментарии запланированы в следующих версиях. Пояснения в примерах
этого справочника, отмеченные `←`, - не часть кода.

**Зарезервированные слова:** `if`, `else`, `choice`, `goto`, `halt`, `true`,
`false`. Зарезервированы везде в строке (как идентификаторы), не только в начале, поэтому команду или переменную так назвать нельзя.

**Экранирования нет.** Обратная косая `\` - обычный символ, а `[` в реплике
всегда открывает тег. Единственная "экранированная" последовательность - тег
`[\n]` (перенос строки). Поэтому в текущей версии нельзя записать:

- литеральную `[` в тексте реплики (`]` можно - без открывающей она просто текст);
- реплику, состоящую из одной `}` - такая строка закрывает блок;
- реплику с отступом в начале - ведущие пробелы и табы отбрасываются, как и в коде;
- пустую реплику - пустые строки игнорируются;
- двойную кавычку `"` внутри текста кнопки `choice` и строкового аргумента.

`;`, `#`, `{` и прочие символы внутри реплики - обычный текст.

**Имя не может начинаться с цифры.** В некоторых позициях (`[ico]`, строковые
аргументы `[cmd]`) легальны и число, и имя, и различаются они только по первому
символу: `[ico 2nd_form 0]` - ошибка компиляции.

## 3. Режимы: монолог и диалог

Директива формата задаёт, для чего файл предназначен, и компилятор следит,
чтобы автор не использовал средства, несовместимые с выбранным режимом.

| | Монолог | Диалог |
|---|---|---|
| Игра на фоне | продолжается | ставится на паузу |
| Позиция окна | `[pos x y]` | статическая, задаётся стилем окна |
| `choice` | **ошибка компиляции** | разрешён |
| `[await $flag]` | разрешён | **ошибка компиляции** |
| `[input $g]` | **ошибка компиляции** | разрешён |
| `[pos x y]` | разрешён | **ошибка компиляции** |

Логика простая: в монологе игрок продолжает играть, поэтому окно надо где-то
разместить и можно ждать игровых событий, но нельзя показывать кнопки выбора.
В диалоге всё наоборот - игра стоит, ждать игровых событий бессмысленно, зато
доступен выбор.

Остальные средства языка работают в обоих режимах одинаково.

## 4. Регионы, точки и переходы

### Регионы

Регион - именованный участок скрипта, ограниченный парой строк:

```
:QUEST_start
	...
:QUEST_end
```

Имя региона - то, что стоит перед суффиксом (`QUEST`). Оба маркера
чисто структурные: они ничего не делают во время выполнения, не создают
области видимости и не подразумевают возврата. Это просто якоря для переходов.

Важное следствие: выход за `:NAME_end` ничего не останавливает. Управление
просто перетечёт в следующую инструкцию файла. Если этого не нужно - закончите
регион явным `halt` или переходом.

### Переход на регион

Голое имя с двоеточием - переход на начало одноимённого региона:

```
:QUEST
```

Это то же самое, что "прыгнуть на `:QUEST_start`". Возврата нет: язык не имеет
вызова с возвратом, переход односторонний.

### Точки

Точка - метка на конкретном месте в коде, объявляется двойным двоеточием:

```
::CHECKPOINT
```

Переход на точку делается ключевым словом `goto`:

```
goto CHECKPOINT
```

### Различие, которое легко забыть

- `:NAME` ведёт только на регион (дописывает `_start`)
- `goto NAME` ведёт только на точку (имя берётся как есть)

`goto QUEST` не попадёт в регион `QUEST_start` - будет ошибка "Точка 'QUEST' не
найдена", и компилятор подскажет, что есть регион с таким именем. И наоборот.

Регионы и точки при этом живут в **одном пространстве имён адресов**, поэтому
регион `FOO_start` и точка `::FOO_start` конфликтуют.

### Что означает строка `:X`

Одно и то же написание `:X` значит разное - в зависимости от имени и от того,
что стоит на следующей строке. Компилятор разбирает его так, по порядку:

| Строка | Значит |
|---|---|
| `:X`, а на следующей строке `{` | вызов компонента `X` (неизвестное имя - ошибка) |
| `:X` без блока, где `X` - имя компонента | ошибка: у компонента нет тела |
| `:ИМЯ_start` | начало региона `ИМЯ` |
| `:ИМЯ_end` | конец региона `ИМЯ` |
| любое другое `:X` | переход на регион `X` |
| `::X` | точка `X` - отдельная конструкция, к правилам выше не относится |

Отсюда два ограничения на имена регионов - иначе на регион нельзя было бы
перейти, и компилятор считает это ошибкой:

- регион не может называться как компонент (`text_Default`, `text_Right`,
  `text_Left`, `global_set`, `command_call`): `:text_Default` - это вызов
  компонента;
- имя региона не может кончаться на `_start` или `_end`: строка `:a_start` - это
  начало региона `a`, а не переход на регион `a_start`.

На точки эти ограничения не распространяются: `::text_Default` и
`::a_start` допустимы, потому что на точку переходят через `goto`, у которого
своё написание.

### Направление перехода

Прыгать можно и вперёд, и назад - порядок объявления в файле роли не играет.
Переход на ещё не встреченную метку разрешается компилятором позже
автоматически.

### Остановка

```
halt
```

Останавливает выполнение. В конце файла подразумевается неявно, так что писать
его последней строкой не требуется - только там, где надо оборвать поток
раньше.

## 5. Компонентные функции

Вызов компонента - имя с двоеточием и блок:

```
:имя
	{
	...
	}
```

Компонентов ровно пять, все встроенные. Делятся по типу тела.

### Текстовые компоненты

Тело - текст реплик. Отличаются стилем окна - например, направлением "хвоста"
(как именно он выглядит, решает тема на стороне платформы):

| Вызов | Стиль окна | Иконки |
|---|---|---|
| `:text_Default` | без хвоста | **нельзя** |
| `:text_Right` | хвост справа | можно |
| `:text_Left` | хвост слева | можно |

```
:text_Right
	{
	Первая строка реплики.
	Вторая строка того же окна.
	}
```

Каждая строка внутри блока - отдельная "реплика": после неё выполнение
приостанавливается, пока движок не сообщит, что можно продолжать. Последняя
строка блока помечается особо, чтобы движок знал, что окно отработало.

### Кодовые компоненты

Тело - обычный код, как на верхнем уровне. Это группирующие обёртки для
читаемости, семантики своей не несут:

```
:global_set
	{
	$quest_marble = 1
	$quest_flag_B = false
	}
```

```
:command_call
	{
	[cmd mono_toggle true]
	[cmd shake 5]
	}
```

Ровно тот же эффект получится, если написать эти строки без обёртки - она
нужна только чтобы сгруппировать связанные действия.

## 6. Текст и теги

Внутри текстового блока каждая строка - это чередование обычного текста и
тегов в квадратных скобках:

```
[pos 345 500]lorem ipsum dolor sit[spd 0.2]...[spd 1][\n]amet...
```

Текст между тегами берётся как есть, включая пробелы. Тег может стоять в любом
месте строки, в том числе в начале и в конце.

### Справочник тегов

| Тег                   | Аргументы                      | Что делает                                                | Ограничения         |
| --------------------- | ------------------------------ | --------------------------------------------------------- | ------------------- |
| `[\n]`                | -                              | Перенос строки внутри окна                                |                     |
| `[pos x y]`           | два целых числа                | Позиция окна на экране                                    | только монолог      |
| `[spd n]`             | число или переменная           | Сменить скорость печати с этого места                     |                     |
| `[ico id frame]`      | id или имя, целый кадр         | Показать иконку (кадр из sprite-sheet)                    | не в `text_Default` |
| `[wait n]`            | неотрицательное число          | Пауза на n секунд                                         |                     |
| `[await $flag]`       | глобальная `bool`              | Ждать, пока платформа не сообщит, что `$flag` стал `true` | только монолог      |
| `[input $g]`          | глобальная `number` или `text` | Ждать, пока игрок введёт значение                         | только диалог       |
| `[auto]`              | -                              | Строка не требует отклика игрока                          |                     |
| `[cmd имя аргументы]` | по манифесту                   | Вызвать игровую команду                                   |                     |
| `[имя]`               | -                              | Подставить значение переменной                            |                     |

### Подробности по отдельным тегам

`[spd n]` влияет на печать начиная с места, где стоит, до следующего `[spd]`
или конца реплики. Что именно означает число - дело движка (обычно секунды на
символ или множитель скорости).

`[ico id frame]` принимает числовой id иконки напрямую **или** имя из
enum-секции спрайтов (для имени нужен манифест). Какая секция манифеста отвечает за спрайты, язык не знает:
её имя задаётся в настройках компилятора (`CompilerOptions.IconSection`, в IDE -
настройка проекта). Если настройка пуста, `[ico]` принимает только числа.
Компилятор проверяет по манифесту, что такая иконка есть и что номер кадра не
выходит за пределы её sprite-sheet.

`[wait n]` останавливает выполнение на заданное время. Стоит помнить, что
пауза посреди реплики делит её надвое: движок получает текст до `wait`,
печатает, выжидает, и только потом получает остаток - в то же самое окно, оно
не закрывается.

`[await $flag]` останавливает выполнение, пока платформа не сообщит, что
глобальная `$flag` стала `true`. Условие проверяет не VM, а платформа: VM
только встаёт на паузу и запоминает, какую глобальную ждут. Чем именно
является условие (клик в зоне, вход в триггер, смена флага) - целиком дело
игры. Глобальная должна иметь тип `bool`; производная (`stored: false`)
допустима - это как раз типичный случай вроде `$tutorial.p_clicked`.

`[auto]` - подсказка движку, что эту строку можно не ждать. Позиция внутри
строки роли не играет, тег относится ко всей строке. Движок вправе подсказку
проигнорировать, например если игрок включил "всегда ждать подтверждения".
Такой настройки в языке нет: её реализует платформа, при желании - через свою
команду.

`[cmd имя аргументы]` вызывает команду, объявленную в манифесте. Обёртка
`cmd` обязательна: она отделяет игровые команды от встроенных тегов языка.
Количество и типы аргументов сверяются с манифестом (полное описание полей -
в [README](../README.md#приложение-б-шаблон-манифеста)):

| Тип в манифесте | Что принимается |
|---|---|
| `number` | число (в том числе отрицательное и дробное), локальная или глобальная типа `number` |
| `bool` | только `true` или `false` (не `0`/`1`), либо глобальная типа `bool` |
| `string` | имя из enum-секции аргумента (`enum_section`), без кавычек или в кавычках, либо его числовой id. Переменные - нет |

```
[cmd unlock OakBark]
[cmd unlock "OakBark"]
[cmd unlock 2]
```

Все три строки компилируются одинаково: в байткод идёт только id.

Аргументы с `default` в манифесте можно опускать - но только хвостом, с конца.
Недостающие значения подставляет компилятор в момент компиляции, как
константы: VM о дефолтах не знает ничего. Следствие: если автор команды сменил
`default` в манифесте, уже скомпилированные `.qbc` сохранят старое значение до
перекомпиляции.

Переменные в аргументах тегов допустимы только там, где VM снимает значение
со стека: в `number`/`bool`-аргументах `[cmd]` и в `[spd]`.

```
[cmd shake $power]
[spd tempo]
```

Проверяется только тип, значение переменной неизвестно до запуска. В остальных
тегах (`[pos]`, `[ico]`, `[wait]`) и в enum-аргументах - только литералы.
Отрицательные числа допустимы везде (`[pos -20 100]`). Выражений в аргументах
тегов нет.

`[input $g]` останавливает выполнение, пока игрок не введёт значение.
Поле ввода рисует игра (как кнопки у `choice`), она же записывает результат в
глобальную `$g`, после чего выполнение продолжается. Глобальная должна иметь тип
`number` или `text` (для да/нет есть `choice`) и не быть производной. Если тег
стоит посреди реплики, окно с вопросом остаётся на экране, пока игрок печатает:

```
:text_Default
	{
	Как тебя зовут?[input $player.name]
	Тебя зовут [$player.name]!
	}
```

Интерполяция. Если имя в скобках не совпало ни с одним известным тегом, оно
трактуется как имя переменной, и вместо тега подставится её значение:

```
Теперь у тебя [qm] богатств!
Флаг равен [$quest_flag_A].
```

## 7. Переменные и выражения

### Глобальные и локальные

- `$имя` - **глобальная**: живёт в игре, объявлена в манифесте, переживает
  диалог и сохранения
- `имя` - **локальная**: живёт в пределах одного скомпилированного файла

Глобальные объявлять в скрипте не нужно (и нельзя) - они приходят из манифеста.
Обращение к глобальной, которой нет в манифесте, - ошибка компиляции.

Глобальная типа `text` (например, имя игрока) допустима только в
интерполяции `[$имя]` и в `[input]`: в выражениях, условиях, присваиваниях и
аргументах команд она даёт ошибку компиляции. Локальных текстовых переменных
нет.

### Объявление локальной

```
int qm = $quest_marble + $quest_ring
```

Тип обязателен при объявлении. Сейчас поддерживается один тип - `int`.
Переобъявление той же локальной - ошибка, использование до объявления - тоже.

`int` - целое при записи. Вычисления идут в дробных числах, а в локальную
попадает целая часть (отбрасывается к нулю): `int x = 5 / 2` даёт `2`, но
`if 5 / 2 == 2` - ложь. Деление на ноль не ошибка: результат - самое большое
целое (`2147483647`) для положительного делимого, самое маленькое
(`-2147483648`) для отрицательного и `0` для нуля. В тексте `[x]` выводится
без дробной части и разделителей разрядов. Точные правила - в
[спецификации байткода](../README.md#числа).

### Области видимости

Область видимости создают только ветки `if` и `else`. Регионы, `:global_set`
и `:command_call` областей не создают: регион - структурный якорь, а обёртки по
определению эквивалентны коду без них.

```
int top = 1
if top == 1
	{
	int t = 5  ← видна до закрывающей скобки ветки
	}
else
	{
	int t = 6 ← можно: это другая область, соседняя
	}
int t = 7 ← можно: предыдущие t уже не видны
```

- Затенение запрещено. Объявить во вложенной области имя, которое видно из
  внешней, - ошибка: в диалоговых скриптах это почти всегда опечатка.
- Метка внутри блока после локальной запрещена. Точка `::NAME` или начало
  региона не может стоять в ветке `if`/`else` после объявления локальной,
  видимой в этом месте (кроме объявленных на верхнем уровне файла): переход на
  такую метку извне пропустил бы инициализацию переменной. Метка **до**
  объявления разрешена.
- Переход не может перепрыгнуть объявление локальной верхнего уровня, если
  после цели перехода она используется: объявление не выполнилось бы, и
  переменная хранила бы `0` или - на повторном проходе по кругу - старое
  значение. Как `goto` в C++, который не может обойти инициализацию:
```qdscr
   int i = 0
   ::Loop
   if i == 1
   	{
  	goto Skip ← ошибка: перепрыгивает объявление x
   	}
   int x = 5
   ::Skip
   :text_Default
   	{
  	[x]  ← а здесь x используется
   	}
```
 
Правило касается `goto`, перехода на регион и вариантов `choice`. Переходы назад и переходы, после цели которых переменная не встречается, разрешены. "Используется после цели" проверяется по положению в файле, а не по путям исполнения, поэтому изредка ошибка ложная - когда код после цели достижим только через объявление. Снимается она переносом объявления выше перехода.

- Локальная верхнего уровня, через объявление которой перепрыгнули вперёд
  через `goto`, читается как `0`.

### Присваивание

```
$quest_marble = 1
qm = qm + 1
```

### Выражения

Операторы, по убыванию приоритета:

1. `-` унарный минус, скобки `( )`
2. `*` `/`
3. `+` `-`
4. `==` `!=` `<` `>` `<=` `>=`

Сравнения не сцепляются: `a < b < c` недопустимо.

Операнды: числа (`1`, `0.5`), `true`/`false`, ссылки на переменные, скобочные
подвыражения.

```
int total = ($quest_marble + $quest_ring) * 2
if total >= 10
	{
	...
	}
```

Внутри тегов выражений нет: `[cmd shake $power * 2]` работать не будет.

## 8. Условия

```
if $quest_flag_A == true
	{
	:text_Default
		{
		Ты уже говорил со мной.
		}
	}
else
	{
	:text_Default
		{
		Приятно познакомиться.
		}
	}
```

Ветка `else` необязательна. Вложенность любая. Значение условия трактуется как
ложное, если равно нулю.

## 9. Выбор

Доступен только в режиме диалога.

```
choice
	{
	-> "Выстрелить" :BIGSHOT
	-> "Стерпеть" goto Doom
	}
```

Каждый вариант - стрелка, текст кнопки в двойных кавычках и цель перехода.
Цель задаётся в одной из двух форм, тех же, что и вне выбора:

- `:РЕГИОН` - переход на регион (дописывается `_start`)
- `goto ТОЧКА` - переход на точку

Внутри блока `choice` допустимы только строки вариантов - ни текста, ни
условий, ни вложенных конструкций.

Ветки не возвращаются. После выбора управление уходит по адресу и течёт
дальше по файлу. Конец каждой ветки надо оформить явно - `halt`, переход или
намеренное перетекание в следующий регион.

Реплика-вопрос перед выбором пишется отдельным текстовым блоком выше.

## 10. Теги вне текста

Четыре тега можно ставить как самостоятельные конструкции, вне текстового блока
(с теми же ограничениями режимов: `[await]` - только в монологе, `[input]` -
только в диалоге):

```
[cmd mono_toggle true]
[wait 2]
[await $player_entered_zone]
[input $shop.qty]
```

Это нужно, когда действие не привязано к реплике - например, переключить режим
до появления первого окна или подождать в ветке `if`, где текста нет. Без этого
пришлось бы заводить пустое окно только ради того, чтобы куда-то поместить тег.

Остальные теги (`pos`, `spd`, `ico`, `\n`, `auto`, интерполяция) описывают
окно или строку, поэтому вне текста бессмысленны и вызывают ошибку.

## 11. Манифест

Манифест - JSON-файл, который рекомендуемо печёт платформа (движок, игра) и читает
компилятор. Это единственный источник сведений об игровой стороне: какие
есть команды и с какими аргументами, какие есть глобальные переменные,
перечисления и иконки. Полный шаблон и описание всех полей - в
[README](../README.md#приложение-б-шаблон-манифеста); здесь - то, что важно знать автору
сценариев.

- Команды вызываются как `[cmd имя ...]`. Имена плоские: `namespace` из
  манифеста в скрипте не пишется, он нужен только для группировки в
  инструментах.
- `deprecated` - команда работает, но устарела: компиляция пройдёт с
  предупреждением.
- `absent` - команда или значение перечисления удалены. Ошибка будет внятной
  ("команда удалена", "значение удалено"), а не "неизвестная".
- Аргументы с `default` можно опускать, но только хвостом, с конца.
  Значение подставляет компилятор, поэтому после смены `default` в манифесте
  сценарии нужно перекомпилировать.
- Строковые аргументы - это имена из перечисления (`enum_section`), а не
  произвольный текст.
- Глобальные берутся из манифеста, неймспейс - часть имени:
  `$tutorial.p_clicked`.
  - `stored: false` - производная: читать можно, записывать нельзя.
  - тип `text` - только для интерполяции `[$имя]` и `[input]`.
- `icons` - сколько кадров у каждой иконки: по нему проверяется второй
  аргумент `[ico]`.
- `version` штампуется в скомпилированный `.qbc`. Если сценарии собраны под
  манифест новее, чем знает платформа, она сообщит об этом при загрузке, вместо
  того чтобы тихо вызвать не ту команду.

Без манифеста компилируются только средства языка: текст, теги подачи,
локальные, условия, `choice`, переходы. Команды, глобальные, иконки по имени и
строковые аргументы дают ошибку "... требует манифест, а он не задан".

## 12. Что получается на выходе

Компиляция одного исходного файла даёт два файла.

**`.qbc`** - байткод: инструкции, числовые константы, версия манифеста, режим
формата. Ни одной строки текста внутри нет - все имена команд, переменных и
иконок уже разрешены в числовые id.

**`.qstr`** - таблица строк: весь отображаемый текст, по одной записи на строку,
с числовым id. Локализация делается заменой этого файла: рядом кладётся
`Имя_ru.qstr`, `Имя_en.qstr` и так далее, а байткод остаётся неизменным и
перекомпиляции не требует.

Локаль указывается в имени файла, а не в расширении: так платформа видит все
языки как один тип ресурса.

Что перезаписывается при перекомпиляции. Компилятор пишет `.qstr` только
той локали, на которой написан сам сценарий. Файлы остальных локалей он не
трогает вообще: они самостоятельны и правятся отдельно. Обратная сторона -
изменившийся сценарий и отставший перевод расходятся молча, поэтому переводы
стоит сверять по id (каких записей в переводе не хватает). IDE делает это сама
при открытии перевода.

## 13. Ошибки и предупреждения

Компилятор не останавливается на первой ошибке: он собирает все, какие
найдёт, и у каждой указывает строку и столбец. Сломанная конструкция
пропускается до конца своей строки (а если за ней шёл блок `{ }` - вместе с
блоком), сломанный тег - до своей `]`, и разбор продолжается. На одну позицию
выдаётся не больше одной ошибки. Если есть хоть одна ошибка, `.qbc` и `.qstr` не
создаются.

Одна настоящая ошибка иногда тянет за собой следствия: пропущенная `}`, например,
даёт "Блок не закрыт: нет парной '}'" у каждого объемлющего блока. Исправлять
стоит сверху вниз.

В таблице - начало сообщения; полный текст обычно поясняет, что делать.

Наиболее частые сообщения:

| Сообщение                                                                        | Причина                                                                                              |
| -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `Компонент 'text_Default' вызывается как ':text_Default'`                        | Пропущено двоеточие перед именем компонента                                                          |
| `У компонента ':X' нет тела`                                                     | Забыт блок `{ }` после компонента                                                                    |
| `Текстовый блок ':X' пуст`                                                       | Окно без единой строки                                                                               |
| `Лишнее в конце строки`                                                          | После конструкции что-то дописано                                                                    |
| `Неизвестная команда 'X'`                                                        | Команды нет в манифесте                                                                              |
| `Команда 'X' удалена из манифеста`                                               | Команда помечена `absent`                                                                            |
| `Команда 'X' ожидает N аргумент(ов)`                                             | Не совпало число аргументов (с учётом `default`)                                                     |
| `значения 'X' нет в секции 'S'`                                                  | Имени нет в enum-секции аргумента                                                                    |
| `ожидалось true, false или bool-глобальная`                                      | В `bool`-аргумент передано число                                                                     |
| `Неизвестная глобальная переменная 'X'`                                          | Глобальной нет в манифесте                                                                           |
| `Глобальная 'X' производная (stored: false)`                                     | Запись в производную глобальную                                                                      |
| `Локальная 'X' не объявлена`                                                     | Использование до объявления или вне области                                                          |
| `затенение запрещено`                                                            | Имя уже видно из внешней области                                                                     |
| `Точка стоит внутри блока после объявления локальной` (или `Начало региона ...`) | См. [раздел 7](#7-переменные-и-выражения)                                                            |
| `choice допустим только в режиме диалога`                                        | Нарушен режим формата                                                                                |
| `[pos] допустим только в режиме монолога`                                        | Нарушен режим формата                                                                                |
| `[input] допустим только в режиме диалога`                                       | Нарушен режим формата                                                                                |
| `имеет тип text: такая глобальная допустима только в интерполяции`               | Текстовая глобальная в выражении, условии или присваивании                                           |
| `'$X' имеет тип bool, а ожидается number`                                        | Переменная не того типа в аргументе `[cmd]`/`[spd]`                                                  |
| `[ico] допустим только внутри :text_Right/:text_Left`                            | Иконка в окне без хвоста                                                                             |
| `... требует манифест, а он не задан`                                            | Команда, глобальная, иконка по имени или строковый аргумент без манифеста                            |
| `иконки по имени недоступны`                                                     | Манифест есть, но не задана секция иконок в настройках компилятора                                   |
| `Имя 'X' начинается с цифры`                                                     | Имя там, где допустим и числовой id (`[ico 2nd_form 0]`)                                             |
| `Аргумент тега должен быть литералом`                                            | Выражение в аргументе тега (`[cmd shake $power * 2]`)                                                |
| `Кадр N вне диапазона`                                                           | Номер кадра больше, чем есть в sprite-sheet                                                          |
| `Точка 'X' не найдена` / `Регион 'X' не найден`                                  | Переход на несуществующую метку (если есть метка другого вида с тем же именем, компилятор подскажет) |
| `Неизвестный тип '#'`                                                            | Строка не похожа ни на одну конструкцию - например, попытка комментария                              |
| `Тег '[X]' допустим только внутри текстового блока`                              | Оконный тег вынесен наружу                                                                           |
| `[await] ждёт bool-глобальную`                                                   | В `[await]` передана глобальная типа `number`                                                        |
| `Регион не может называться 'X'`                                                 | Имя региона совпадает с именем компонента (см. [раздел 4](#4-регионы-точки-и-переходы))              |
| `Имя региона 'X' кончается на _start` / `_end`                                   | На такой регион нельзя перейти (см. [раздел 4](#4-регионы-точки-и-переходы))                         |
| `Переход на 'X' перепрыгивает объявление локальной 'y'`                          | См. [раздел 7](#7-переменные-и-выражения)                                                            |
| `Имя 'X' занято встроенным тегом`                                                | Локальная названа как тег (`int auto = 1`)                                                           |
| `Не закрыт тег: нет парной ']'`                                                  | `[` без `]` - в том числе попытка написать `[` как текст                                             |

Предупреждения не прерывают компиляцию:

- `Команда 'X' устарела` - обращение к команде с пометкой `deprecated`;
- `Регион 'X' не закрыт: нет ':X_end'` и `':X_end' без парного ':X_start'` - на
  исполнение не влияют.

## 14. Ограничения

Текущая версия языка (1.0) не поддерживает - пункты с `*` запланированы в
следующих версиях (см. [README](../README.md#дальнейшие-планы)):

- Комментарии `*`
- Экранирование - см. [раздел 2](#2-общие-правила-синтаксиса)
- Произвольные строки в аргументах команд - тип `string` означает имя из
  enum-секции, а не свободный текст
- Выражения в аргументах тегов - только литералы и (в `[cmd]`/`[spd]`) переменные
- Операции над текстом - текстовые глобальные можно только вывести и ввести
- Условные варианты выбора `*` - кнопку нельзя показать по флагу
- Динамические списки вариантов
- Вызов с возвратом - переходы односторонние (осознанно)
- Циклы как отдельная конструкция (делаются переходом назад на точку)
- Типы кроме `int`
- Логические операторы `&&`, `||`, `!` `*`

## 15. Полный пример

```
@dialogue_format_dialogue

:MAIN_start
:text_Right
	{
	[ico 0 0]А волк ему и говорит[spd 0.2]...[spd 1][\n]Погоди-ка, что-то здесь не так...
	}
:text_Right
	{
	[ico 0 3]Вы укрываете у себя пособников рейха?![cmd shake 1]
	}

if $quest_flag_A == true
	{
	:text_Left
		{
		[ico 1 2]Признаться, мне надоел этот фарс.
		}
	choice
		{
		-> "Выстрелить" :BIGSHOT
		-> "Стерпеть" goto Doom
		}
	}
else
	{
	::Doom
	:text_Right
		{
		[ico 0 3]Пожалуй, нам с вами говорить больше не о чем...
		}
	:text_Default
		{
		[cmd shake 0.5]*Слышны звуки выстрелов
		}
	if $quest_ring == 0
		{
		:text_Default
			{
			*Квест провален
			}
		:global_set
			{
			$quest_flag_B = false
			}
		}
	}

::Flag
:text_Default
	{
	*Дальнейшая судьба неизвестна
	}
halt
:MAIN_end

:BIGSHOT_start
:text_Default
	{
	[cmd shake 0.5]*Слышны звуки выстрелов[spd 0.1]...[wait 1][\n]Но...[spd 1]
	}
:text_Left
	{
	[ico 1 3]Кха-пх...[spd 0.9][\n]Уф...[spd 1]
	}
:text_Default
	{
	*Кто-то выжил
	}
goto Flag
:BIGSHOT_end
```
**Предполагается, что под данный пример написан обособленный манифест, позволяющий корректно скомпилировать скрипт.**

## Приложение: сводка синтаксиса

```
@dialogue_format_monologue  ←директива режима (первая строка)
@dialogue_format_dialogue

:NAME_start  ←начало региона
:NAME_end  ←конец региона
:NAME  ←переход на регион NAME_start
::NAME  ←объявление точки
goto NAME  ←переход на точку
halt   ←остановка

:text_Default  { ... }  ←окно без хвоста, тело - текст
:text_Right    { ... } ←окно с хвостом справа
:text_Left     { ... } ←окно с хвостом слева
:global_set    { ... } ←группировка, тело - код
:command_call  { ... } ←группировка, тело - код

if <выражение>  ←условие
	{ ... }
else
	{ ... }

choice  ←выбор (только режим диалога)
	{
	-> "текст" :РЕГИОН
	-> "текст" goto ТОЧКА
	}

int имя = <выражение>  ←объявление локальной
имя = <выражение> ←присваивание локальной
$имя = <выражение>  ←присваивание глобальной

[\n] [pos x y] [spd n]  ←теги внутри текста
[ico id|имя f]
[wait n] [await $f] [auto]
[cmd имя аргументы] [переменная]

[input $g]  ←(только диалог)

[cmd ...] [wait n] [await $f]  ←теги как самостоятельные конструкции
[input $g]
```

Спецификация байткода (`.qbc`, `.qstr`, опкоды, модель исполнения) и шаблон
манифеста - в [README](../README.md#приложение-а-спецификация-байткода).
